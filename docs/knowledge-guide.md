# 知识库配置指南

AI 管理员 / 咨询助手采用「README 索引 → 按需读取文档 → 附带回答规范」的两段式：第一次请求只附带 `README.md` 索引（每篇文档的书名与关键字），模型通过 `read_knowledge` 读取相关文档；读取成功后，第二次请求再附上文档全文和 `00-回答规范.md`。本文说明知识库放在哪里、如何指定目录、文档怎么写，以及常见问题排查。

## 工作流

```text
新弹幕 → 按房间聚合 → 去重/过滤
                          ↓
          第一次 LLM 请求（附 README.md 索引）
                          ↓
             模型判断是否有咨询/求助
               ↓ 需要查资料              ↓ 无需回复/闲聊
      read_knowledge 读取相关文档              [SKIP]
               ↓ 工具结果回填
     第二次 LLM 请求（文档全文 + 00-回答规范.md）
               ↓
          生成回复 → 发送弹幕 → 日志记录来源
```

这样设计的目的：

1. **节省 token**：第一次请求只带 README 索引，不把全部知识文档塞进提示词；模型只为当前问题读取相关文档。
2. **回答更准**：第二次请求拿到完整文档和统一回答规范，不依赖关键词片段拼接。
3. **保留降级能力**：如果服务端拒绝 `tools` 参数（HTTP 400），会自动改用本地 BM25 检索片段 + 回答规范再试一次，并在日志里记录「模型不支持工具调用」。

知识库检索是**可选能力**，由控制台的「启用知识库检索」开关控制。关闭后不附带索引、不注册读取工具，也不注入回答规范。

### 主播本人弹幕

主播自己发的弹幕不会触发 AI 回复，也不会进入“最近弹幕上下文”，避免直播间观众看到主播自答自话。

- 优先按主播 `uid` / `secUid` 与弹幕发送者精确比对；
- 主播信息只解析到昵称时，才退化为昵称比对；
- 主播信息是异步补全的：弹幕入队时过滤一次，真正调用 LLM 前再用最新主播信息过滤一次；
- 主播信息完全取不到时不做过滤（避免误伤同名 / 同 id 的普通观众），日志里也不会出现“已忽略主播弹幕”。

### 多观众回复

模型需要按观众返回 JSON，例如：

```json
{
  "1": { "player_name": "又睡了一天", "content": "这游戏叫《试炼之地》，发宗门名就能加入。" },
  "2": { "player_name": "侠哥哥", "content": "目前有十一个宗门，直接发宗门名就能加入。" }
}
```

系统会解析 JSON，把每个 `content` 拆成一条独立弹幕，**一个观众回复一条**，相邻两条默认间隔 3 秒发送，避免连续发言触发风控。间隔可在控制台 AI 设置「多条回复间隔」中调整，也可用 `DYHUB_AI_REPLY_INTERVAL_MS` 设置默认值；实际发送还会经过采集层的同房间发送队列（`DYHUB_CHAT_INTERVAL_MS`，默认也是 3 秒），因此真实间隔不会小于这两个值。也兼容数组、`{"replies":[...]}` 外壳和旧版纯文本输出；同一观众的重复条目会去重，单轮最多发送 10 条。

重复弹幕的处理：

- 同一批弹幕里内容相同的只处理一次，只回复第一个观众；
- 处理过的内容在「重复弹幕忽略」窗口内再次出现时直接跳过，不调用模型、不发送；窗口默认 300 秒，可在 AI 设置中修改，设为 `0` 关闭；
- 比较前会做归一化，忽略空格、标点和大小写，所以「怎样玩？」「怎样玩 ?」算同一条；
- 模型判断无需回复时，这批弹幕也会记为已处理，避免同样的 spam 每隔一个间隔就重新问一次模型；
- 同一观众一轮最多回复一条；只有发送成功的观众会被标记为已处理，发送失败的下轮还能重试。

提示：去重按**内容**判断，不区分发送者。如果两位观众在窗口内发了完全相同的话，只会回复第一位。

## 默认位置

默认目录：

```text
<运行目录>/data/knowledge/
```

本地开发时通常是：

```text
D:\workspace\qunxia\dyhub\data\knowledge
```

Docker 中运行目录是 `/app`，默认对应容器内 `/app/data/knowledge`。官方 `docker-compose.yml` 已把 `./data` 挂载到 `/app/data`，因此默认知识库会随 `data/` 一起持久化。

`data/` 已在 `.gitignore` 中，知识文档不会提交到代码仓库。

## 如何指定目录

支持三种方式，优先级从高到低：

1. 控制台 / API 保存的 `knowledgeDir`
2. 环境变量 `DYHUB_KNOWLEDGE_DIR`
3. 默认 `data/knowledge`

### 方式一：控制台（推荐）

1. 打开控制台 `http://localhost:8757`
2. 左侧「AI 管理员 / 咨询助手」
3. 展开「知识库文档（目录可配置）」
4. 在目录输入框填写路径，例如 `D:\dyhub-kb`、`/srv/dyhub-kb` 或 `data/kb`
5. 点「应用目录」

输入框下方会显示解析后的真实绝对路径。目录不存在时会自动创建，文档列表会立即刷新，无需重启服务。

### 方式二：环境变量（部署默认值）

```bash
DYHUB_KNOWLEDGE_DIR=/srv/dyhub-kb npm run dev
```

Docker Compose 示例：

```yaml
services:
  dyhub:
    environment:
      DYHUB_KNOWLEDGE_DIR: "/kb"
    volumes:
      - ./data:/app/data
      - ./knowledge:/kb
```

环境变量只作为**默认值**：如果 `data/ai-chat.json` 里已经保存过 `knowledgeDir`，则以保存值为准。想改回环境变量指定的目录，在控制台重新点「应用目录」或删除配置里的 `knowledgeDir` 字段后重启。

### 方式三：API

```bash
curl -X PUT http://localhost:8757/api/ai-chat \
  -H 'Content-Type: application/json' \
  -d '{"knowledgeDir":"D:/dyhub-kb"}'
```

返回中会包含：

```json
{
  "ok": true,
  "config": {
    "knowledgeDir": "D:/dyhub-kb",
    "knowledgeDirResolved": "D:\\dyhub-kb"
  }
}
```

### 方式四：配置文件

配置持久化在 `data/ai-chat.json`：

```json
{
  "enabled": true,
  "baseUrl": "https://api.openai.com/v1",
  "model": "your-model",
  "knowledgeEnabled": true,
  "knowledgeDir": "data/knowledge"
}
```

手工修改 JSON 后需要**重启服务**才生效；通过控制台或 API 修改则实时生效。

## 路径规则

| 写法 | 示例 | 解析结果 |
| --- | --- | --- |
| 相对路径 | `data/kb` | 相对**进程运行目录**解析 |
| 绝对路径 | `D:\dyhub-kb`、`/srv/dyhub-kb` | 原样使用 |
| 用户目录 | `~/dyhub-kb` | 展开到当前用户主目录 |
| 空值 | `""` | 回退到 `DYHUB_KNOWLEDGE_DIR` 或 `data/knowledge` |

注意事项：

- 目录不存在时会自动创建（包括多级目录）。
- 如果路径指向一个**已存在的文件**而不是目录，保存配置会失败并返回 400。
- 切换目录**不会搬移旧文档**，旧目录里的文件仍留在原处。
- 目录支持中文、空格等字符。

> 安全提示：知识库目录由运行 DyHub 的操作系统账号访问。请确保该账号有读写权限，并不要把目录指向系统敏感位置。

## 文档格式

### 支持的文件

| 项 | 说明 |
| --- | --- |
| 扩展名 | `.md`、`.txt`（大小写不敏感） |
| 编码 | UTF-8 |
| 单文件大小 | ≤ 2MB |
| 目录层级 | **只读取目录第一层**，不递归子目录 |
| 其他文件 | 自动忽略 |

### 两个特殊文件

除了知识文档，目录里还应放两个流程文件：

| 文件名 | 作用 | 何时使用 |
| --- | --- | --- |
| `README.md` | 知识库索引：列出每篇文档的文件名、书名和关键字 | 第一次 LLM 请求时附带，供模型挑选文档 |
| `00-回答规范.md` | 统一的回答格式、语气和禁止事项 | 模型读取文档后，第二次请求时附带 |

`README.md` 示例：

```markdown
# 知识库索引

- `01-产品介绍.md`：书名《试炼之地》；关键字：玩法、宗门、装备、开服时间
- `02-会员与价格.md`：关键字：月卡、季卡、年卡、价格、充值、退款
- `07-玩家常见问题.md`：关键字：换宗门、装备消失、客服、链接
```

`00-回答规范.md` 示例：

```markdown
# 回答规范

- 先给结论，再给必要步骤，一般 2-4 句，单条不超过 120 字。
- 价格、活动、售后政策只按知识文档回答；文档没写就说不确定，不要编造。
- 不要提及知识库、文档、检索、工具或 AI。
```

说明：

- `README.md` 最多附带 4000 字；目录里没有 README 时，系统会自动用文件名生成一个最小索引，但缺少关键字会影响选文档准确率，建议手动维护。
- `read_knowledge` 不能读取 `README.md` 和 `00-回答规范.md`，这两个文件由系统按流程自动附加。
- `00-回答规范.md` 不存在时会在日志里提示，模型仍会继续回答，但建议补上以统一回复风格。

### 内容建议

虽然主流程按 README 选择文档，但控制台「试检索」和工具调用降级仍使用**关键词检索**（中文二元词 + BM25）。文档写法会直接影响检索效果：

1. **按主题分节**：用 Markdown 标题（`#`、`##`）拆分主题，例如「退款流程」「会员价格」「设备连接」。
2. **一节只讲一件事**：避免一整篇超长文档；每个主题尽量控制在 700 字以内。
3. **补充常见说法**：观众可能问「退钱」「退款」「怎么退」，把这些同义词写进正文。
4. **写清条件与步骤**：例如「付款后 7 天内」「在订单页点击申请退款」「审核后 1-3 个工作日原路退回」。
5. **避免大段空白或纯图片**：图片内容无法被检索。
6. **用空行分段**：检索按标题和空行段落切块。

示例：

```markdown
# 退款流程

付款后 7 天内支持无理由退款（退钱 / 退货退款均可）。请在「我的订单」找到对应订单，点击「申请退款」，选择退款原因并提交。

客服审核通过后，款项会在 1-3 个工作日内原路退回。超过 7 天的订单请联系在线客服人工处理。

# 会员价格

月卡 30 元，季卡 80 元，年卡 288 元。开通后立即生效，虚拟商品开通后不支持退款。
```

## 索引与读取规则

- **第一次请求**附带 `README.md` 索引（最多 4000 字），模型据此挑选相关文档。
- 模型调用 `read_knowledge` 时，一次最多读取 **4 篇**文档；单篇最多 4000 字，单次工具结果总预算约 10000 字，超长部分会截断。
- 文档名必须来自 README（容忍大小写、缺少扩展名、引号）；`README.md` 与 `00-回答规范.md` 不能通过工具读取。
- 工具结果回填后、第二次请求前，系统自动附加 `00-回答规范.md`（最多 4000 字）。
- 索引和回答规范不参与本地 BM25 降级检索。
- 控制台「试检索」仍使用本地 BM25：按 Markdown 标题和空行段落切块（每块约 700 字，重叠 100 字），中文按二元词切分，标题、文件名和完整短语命中加权。
- 索引与检索缓存根据文件大小和修改时间自动失效；通过控制台保存或手工修改文件后，下一轮即生效。
- 资料不足时，Agent 会如实说明不确定，不会凭空编造。

因为不是向量检索，**换个说法但没出现任何相同关键词**的问题可能召回不到。把常见同义词写进 README 关键字和文档正文是最有效的优化方式。

## 调试 AI 回复（F3）

调知识库和提示词时，不必真的开播或等弹幕，可以直接用调试面板验证：

1. 在控制台任意位置按 `F3`（或点 AI 面板里的「调试 AI 回复」）打开面板；
2. **每行输入一条**模拟弹幕，格式为 `昵称：弹幕内容`，例如：

   ```text
   鸡蛋：怎么换宗门？换了之后装备会消失吗？
   番薯：月卡多少钱？
   ```

   不写昵称时按「测试观众」处理；空行会被忽略。
3. 点「生成 AI 回复」，或按 `Ctrl / ⌘ + Enter`。

面板会显示：

- AI 生成的弹幕回复；模型同时回复多个观众时会按观众逐条列出（或「无需回复」及模型原始输出 `[SKIP]`）；
- 正式发言时使用的多条回复间隔，以及本批被忽略的重复弹幕数量；
- 实际读取的知识文档来源；
- 索引附带 / 文档读取 / 回答规范注入 / 工具降级等执行步骤；
- 耗时和模型轮数。

调试输入按行拆成独立的模拟弹幕，和正式链路一样会做重复过滤：同一个 `昵称：内容` 写两遍，只会生成一条回复，并在结果里显示「已忽略 N 条重复弹幕」。调试不会写入正式房间的去重缓存，也不会发送弹幕。

调试使用**已保存的 AI 设置**，自动回复开关关闭时也能用；**结果不会发送到直播间**。每次测试会真实请求一次 LLM 接口，可能产生费用。

对应 API：

```bash
curl -X POST http://localhost:8757/api/ai-chat/test-reply \
  -H 'Content-Type: application/json' \
  -d '{"text":"鸡蛋：怎么换宗门？\n番薯：月卡多少钱？"}'
```

返回示例：

```json
{
  "ok": true,
  "skipped": false,
  "reply": "直接发送想加入的宗门名称即可改投……",
  "replies": [
    { "player": "又睡了一天", "content": "直接发送想加入的宗门名称即可改投……" },
    { "player": "侠哥哥", "content": "目前共有十一个宗门，发宗门名即可加入……" }
  ],
  "duplicates": 0,
  "replyIntervalMs": 3000,
  "raw": "……",
  "sources": ["07-玩家常见问题.md"],
  "steps": [
    "已附带知识库索引 README.md",
    "读取知识文档：07-玩家常见问题.md",
    "已附带回答规范 00-回答规范.md"
  ],
  "rounds": 2,
  "elapsedMs": 820
}
```

### 控制台操作

在「知识库文档」面板中：

| 操作 | 说明 |
| --- | --- |
| 新建 | 在「新文档名」输入框填名字（可不带扩展名，自动补 `.md`），点「新建」 |
| 刷新 | 重新读取目录，显示手工复制进来的新文档 |
| 导入 | 选择本地 `.md` / `.txt` 文件，≤ 2MB；同名文件会提示是否覆盖 |
| 编辑 | 选中文档后在文本框修改，点「保存当前文档」 |
| 删除 | 删除当前选中的文档，需二次确认 |
| 试检索 | 输入问题（如「怎么退款」），查看命中的文档、章节和片段 |
| 应用目录 | 切换知识库目录，实时生效 |

目录下方会显示解析后的绝对路径和当前文档数量，例如：

```text
当前目录：D:\workspace\qunxia\dyhub\data\knowledge（3 篇文档）
```

所有操作的成功 / 失败结果都会显示在面板底部的提示行，不再静默失败。AI 回复日志中：

- 「已附带知识库索引」表示第一次请求已带上 README 索引；
- 「读取知识文档」表示模型调用了 `read_knowledge`，日志会列出实际读取的文档；
- 「已附带回答规范」表示第二次请求已附上 `00-回答规范.md`；
- 读取成功的文档会显示在日志来源里（`📚 文档名`）。

## API 参考

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/ai-chat/knowledge` | 文档列表 `{docs:[{name,size,updatedAt}]}` |
| GET | `/api/ai-chat/knowledge/:name` | 读取文档 `{doc:{name,content,...}}` |
| PUT | `/api/ai-chat/knowledge/:name` | 新建或覆盖文档 `{content}` |
| DELETE | `/api/ai-chat/knowledge/:name` | 删除文档 |
| POST | `/api/ai-chat/knowledge/search` | 调试检索 `{query, limit?}` |
| PUT | `/api/ai-chat` | 更新配置，可只传 `{knowledgeDir}` |

示例：

```bash
# 新建 / 覆盖文档
curl -X PUT http://localhost:8757/api/ai-chat/knowledge/faq.md \
  -H 'Content-Type: application/json' \
  -d '{"content":"# 退款流程\n\n付款后 7 天内支持无理由退款。"}'

# 检索测试
curl -X POST http://localhost:8757/api/ai-chat/knowledge/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"怎么退款","limit":4}'

# 切换目录
curl -X PUT http://localhost:8757/api/ai-chat \
  -H 'Content-Type: application/json' \
  -d '{"knowledgeDir":"/srv/dyhub-kb"}'
```

> 文件名必须以 `.md` / `.txt` 结尾，不能包含 `/ \ : * ? " < > |` 等路径或 Windows 非法字符，也不能以 `.` 开头。中文、空格、括号、方括号、`#`、`+` 等常见字符都可以使用；路径分隔符会被去除，无法通过文件名跳出知识库目录。控制台只列出能正常读写的文件，外部复制进来的非法文件名会被忽略。

## Docker 部署

默认 compose 已经把 `./data` 挂载到 `/app/data`，知识库默认就在宿主机的 `./data/knowledge`，无需额外配置。

如果要使用独立目录：

```yaml
services:
  dyhub:
    environment:
      DYHUB_KNOWLEDGE_DIR: "/kb"
    volumes:
      - ./data:/app/data
      - ./knowledge:/kb
```

或者只挂载知识目录，然后通过控制台把 `knowledgeDir` 设置为容器内路径 `/kb`。

注意：容器内路径与宿主机路径不同。控制台里应填写**容器内路径**（如 `/kb`），而不是宿主机路径（如 `D:\dyhub-kb`）。

## 常见问题

### 控制台显示「暂无文档」

- 检查目录输入框下方的「当前目录」是否是预期路径。
- 手工复制文件进目录后，点一下「刷新」。
- 确认文件是 `.md` 或 `.txt`，并且位于目录**第一层**，不在子目录中。
- 文件名不能包含 `/ \ : * ? " < > |`，也不能以 `.` 开头；不合法的文件会被列表忽略。
- 确认运行 DyHub 的账号对该目录有读取权限。

### 试检索没有命中

- 换用文档里实际出现的关键词，例如文档写「退款」，就用「退款」而不是「钱怎么回来」。
- 在文档中补充观众常用的同义词、口语说法。
- 把长文档按主题拆成多个小节，每节聚焦一个问题。

### 保存目录时报错「无法使用知识库目录」

- 路径指向了文件而不是目录。
- 没有创建或写入该目录的权限。
- Windows 盘符不存在或网络路径不可访问。

### AI 没有用上知识库

- 确认「启用知识库检索」已勾选并保存。
- 确认知识库目录第一层有 `README.md`，并列出每篇文档的文件名、书名和关键字；缺少 README 时只能自动生成文件名索引，模型很难判断该读哪篇。
- 确认文档在「当前目录」下，且文件名与 README 中写的完全一致（工具会自动补 `.md` / `.txt`、忽略大小写）。
- 查看 AI 回复日志：
  - 有「已附带知识库索引 README.md」说明第一次请求已带上索引；没有这条通常是知识库开关关闭或目录里没有文档；
  - 有「读取知识文档：…」说明模型已经读取文档，回答仍不对时通常是文档内容没写清或 README 关键字与观众说法差异太大；
  - 有「未找到回答规范 00-回答规范.md」说明规范文件缺失，建议补上；
  - 有「模型不支持工具调用」说明接口拒绝了 `tools` 参数，系统已自动降级为本地检索片段 + 回答规范 + 普通对话；
  - 出现「文档不存在，请从知识库索引中选择文件名」时，检查 README 里的文件名是否和实际文件一致。
- 模型 / 接口建议支持 OpenAI 兼容的 function calling（`tools` / `tool_calls`），否则只能走降级检索。

### 提示「服务端还未加载知识库接口（404）」

说明浏览器里的控制台页面比正在运行的服务端新（通常是改了代码但没有重启服务），或访问到了旧版本的 DyHub。重启 `npm run dev` / `npm start` / Docker 容器后刷新页面即可。控制台 HTML 已设置为每次回源校验，正常不会长期缓存旧页面。

### 提示「文档名不能包含 …」

文件名里带了 `/ \ : * ? " < > |` 等路径或 Windows 非法字符，或没有以 `.md` / `.txt` 结尾。改名后重试即可；中文括号、`#`、`+` 等字符是允许的。

### 回复发送失败或提示超字数

- 调低「回复最大字数」（建议 80-120），或在提示词中要求更精简。
- 抖音输入框对弹幕长度有限制，知识库回答应尽量先给结论，再给必要步骤。

### 修改文档后没有生效

- 索引根据文件修改时间刷新，保存后下一轮检索即生效。
- 某些网络文件系统的时间精度较低，可重新保存一次或重启服务。

## 备份与安全

- 知识库目录不在代码仓库中，请单独备份。
- 文档可能包含价格、售后政策等业务信息，注意访问权限。
- DyHub 控制台和 API 默认没有鉴权，请勿直接暴露到公网。
